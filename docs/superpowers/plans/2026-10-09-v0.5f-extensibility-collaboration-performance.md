# FlickSmith v0.5f Extensibility, Collaboration & Performance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn FlickSmith into a safe professional platform by adding a versioned extension SDK, branch-aware review/collaboration, deterministic render caching and workers, and evidence-based hardware performance gates.

**Architecture:** Extensions declare versioned capabilities and permissions and execute through narrow host contracts rather than gaining arbitrary editor authority. Collaboration is anchored to project branches/checkpoints/frame ranges so review state can detect staleness instead of silently rebasing. Rendering gains content-addressed cache keys derived from immutable render inputs and optional version-matched workers; benchmark claims are generated only from recorded hardware runs.

**Tech Stack:** Node >=22, TypeScript 5.8, Rust 1.88, existing Video Git/timeline branches, JobScheduler, RenderGraph/Render IR, native CPU/WGPU renderer, Tauri/Studio UI, SHA-256 content addressing, Node/Rust tests.

**Spec:** `docs/superpowers/specs/2026-10-09-flicksmith-v0.5-agent-native-creative-platform-design.md`

## Global Constraints

- Extensions get no filesystem, network, shell, credential, GPU, or project-write capability unless it is explicitly declared and granted.
- No extension may bypass typed project mutations, revision checks, semantic locks, or Intent Receipts.
- Collaboration/review metadata never changes project creative state by itself.
- Review anchors reference an exact branch/checkpoint/revision and become stale when that anchor no longer describes the current branch.
- Render cache keys include all inputs capable of changing pixels/audio: project/render-program revision, asset hashes, renderer/backend version, color pipeline/config hash, font/effect/plugin versions, quality settings, and output format.
- A worker executes immutable render jobs only; it never receives general editor/MCP authority.
- Local rendering remains a complete fallback when workers/caches/plugins are unavailable.
- Performance claims must identify hardware/software versions and measured samples; CI must not fabricate cross-machine speed claims.

## Review Focus

- An extension requesting undeclared filesystem/network/shell access must be denied before execution.
- A review comment attached to an old checkpoint must be marked stale rather than silently moving to a different edit.
- Any effect/plugin/color/font change that can alter output must invalidate the relevant render cache entry.
- A worker with incompatible render-contract/runtime versions must reject the job before consuming project assets.
- Performance gates must tolerate normal variance while still detecting meaningful regressions and must not become flaky on generic CI runners.
