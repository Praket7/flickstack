# FlickSmith v0.5d Creative Orchestration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an agent turn a creative brief into a complete, reviewable production plan that chooses existing evidence before generation, executes only typed FlickSmith operations/jobs, builds responsive variants, runs QC, and repairs localized failures.

**Architecture:** Extend the existing Director and Coverage Graph rather than adding a second planner. A validated `CreativeActionPlan` references evidence, generation requests, generated-scene operations, motion operations, sound actions, responsive variants, and QC gates. The executor never runs arbitrary code; it delegates to v3 timeline operations, generation jobs, search/coverage, render, and QC packages and records receipts for every action.

**Tech Stack:** TypeScript 5.8, existing `packages/agent`, semantic search/Coverage Graph, v0.5a v3 operations, v0.5b generation runtime, v0.5c generated scenes, design-QC, Node test runner.

**Spec:** `docs/superpowers/specs/2026-10-09-flicksmith-v0.5-agent-native-creative-platform-design.md`

## Global Constraints

- Search existing media/evidence before generating replacement content.
- Every generation action must include a rationale explaining why source/licensed media does not satisfy the beat.
- Creative plans are declarative data and must reject executable/script fields using the existing opaque-executable guard pattern.
- Execution never mutates project state outside typed revision-safe operations.
- Professional text stays native.
- QC failures produce localized repair actions; they do not trigger full-project regeneration by default.
- Responsive variants share creative intent/assets where possible while allowing aspect-specific layout/motion.

## Review Focus

- A required beat with strong existing evidence must not be replaced by generated media merely because a generator is available.
- Plan execution interrupted halfway must expose completed receipts and leave a valid resumable project.
- A generated asset rejected by QC must not cause unrelated timeline sections to be rebuilt.
- Aspect variants must not silently crop locked/semantic-preserved elements.
- Plans referencing missing assets, providers, compositions, styles, or actions must fail validation before execution.

```ts
export type CreativeAction =
  | { id:string; type:'place_evidence'; beatId:string; assetId:string; start:number; end:number; targetCompositionId:string; rationale:string }
  | { id:string; type:'generate_asset'; beatId:string; request:GenerationRequest; rationale:string }
  | { id:string; type:'build_generated_scene'; beatId:string; sourceActionId:string; request:GeneratedSceneRequest; rationale:string }
  | { id:string; type:'apply_motion'; compositionId:string; operation:V3EditOperation; rationale:string }
  | { id:string; type:'sound'; operation:V3EditOperation|GenerationRequest; rationale:string }
  | { id:string; type:'responsive_variant'; sourceCompositionId:string; aspect:AspectClass; rationale:string }
  | { id:string; type:'qc'; scope:{compositionId?:string;start?:number;end?:number}; rationale:string }
  | { id:string; type:'repair'; issueId:string; rationale:string };

export interface CreativeActionPlan {
  version: 1;
  briefId: string;
  baseRevision: string;
  actions: CreativeAction[];
  dependencies: Record<string,string[]>;
}
```

## Release Gate

v0.5d is complete only when an agent can take a brief plus source media, prove coverage before generation, generate only justified missing material, create editable native generated scenes, execute through typed operations, produce responsive variants, run QC, and repair only failed regions while retaining a complete chain of receipts and revisions.
