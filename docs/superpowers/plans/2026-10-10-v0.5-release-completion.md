# FlickSmith v0.5 Release Completion Plan

## Goal

Ship the complete v0.5 product on `main` with one canonical editable project, full v3 agent control, transactional generation, editable generated scenes, creative orchestration, professional finishing/interchange, extension/collaboration/performance infrastructure, human-craft quality gates, and usable ChatGPT + Work/Codex execution paths.

## Completed stage gates

### v0.5a — Unified V3 Agent Runtime

- Typed v3 MCP operations with expected revisions.
- Intent receipts, checkpoints, semantic locks, undo/redo.
- Motion rigs, responsive variants, cameras, masks/mattes, compositing, tracking, audio analysis and render diagnostics.
- Public RPC acceptance path without arbitrary shell execution.

### v0.5b — Generative Provider Runtime

- Provider-neutral registry and job scheduler.
- Transactional staging, cancellation and explicit acceptance.
- Budget/commercial-rights checks, content-addressed assets and generation provenance.
- OpenAI conversational image adapter with reference-image support and environment credentials.

### v0.5c — Generated Scene Assets

- Direct-alpha, multilayer and segmentation/depth fallback routing.
- Clean-plate reconstruction safety and attachment integrity.
- Native v3 layer/camera assembly with bounded 2.5D motion.
- Generated-scene QC and Studio/MCP lifecycle.

### v0.5d — Creative Orchestration

- Evidence-first Coverage Graph and declarative creative actions.
- Director planning, resumable typed execution, responsive variants and localized repair.
- Human-craft creative gate discouraging generic generated-ad defaults.

### v0.5e — Professional Finish & Interchange

- Managed sRGB, Rec.709, Display-P3, linear-sRGB and ACEScg transforms with D60/D65 adaptation.
- PQ and HLG transfer functions, HDR metadata and waveform/histogram/vectorscope data.
- Explicit native OpenColorIO processor boundary; no false OCIO capability claims when runtime is unavailable.
- OTIO track/clip export and import, FCPXML sequence export, CMX3600 EDL timing and deterministic relink diagnostics.
- LUFS/true-peak normalization planning, ducking, beat analysis, click repair and equal-power crossfades.
- Out-of-process OpenFX host with permitted roots, no shell, crash isolation and timeout termination.

### v0.5f — Extensibility, Collaboration & Performance

- Permissioned extension SDK and conformance rules.
- Revision/checkpoint anchored review threads and approvals with staleness classification.
- Content-addressed semantic render cache keys.
- Immutable version-matched render worker leasing.
- Hardware-fingerprinted benchmark summaries requiring at least three measured samples and matching-hardware regression gates.

## ChatGPT / Work / Codex execution

- `plugin.json` and `skills/flicksmith-setup/SKILL.md` define portable agent onboarding.
- Local execution uses the same repository in Work/Codex/terminal-capable environments.
- Normal ChatGPT can use a deployed FlickSmith backend through `npm run mcp:remote`; the remote transport requires a >=32-character bearer token, explicit browser-origin allowlist, body-size limits and HTTPS termination at the deployment boundary.
- Local desktop HTTP remains loopback-only. Remote exposure is a separate explicit server so desktop security is not weakened.

## Human-craft quality direction

Research and implementation treat generated media as ingredients rather than a visual style. The creative system prefers real source evidence, brand-specific visual grammar, asymmetry, editorial rhythm, selective motion, native typography, restrained transitions, shot-level continuity and localized repair. Generated footage is used only where coverage requires it, and every generated asset retains provenance.

## Final release gates

1. `npm run verify` passes with no failures.
2. Chat portability tests and remote MCP auth tests pass.
3. Native Rust format/clippy/test jobs pass.
4. Windows/macOS/Linux desktop packaging completes; Windows has a deterministic icon fallback for clean checkouts.
5. No temporary diagnostics or CI bypasses remain.
6. `main` is advanced only after the final branch is verified.
