# FlickSmith v0.5b Generative Provider Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a provider-neutral, cancellable, provenance-preserving generation runtime that can generate/edit media without allowing provider failures or secrets to corrupt canonical project state.

**Architecture:** Extend the v3 schema with immutable generation provenance records, then add a new `packages/generation` package that resolves model-generation capabilities and executes work through the existing `packages/jobs` scheduler. Provider outputs remain staged until explicit acceptance; only acceptance imports content-addressed assets and appends generation records to the v3 project through typed mutations. `packages/providers` remains the existing acquisition/rights-provider area; `packages/generation` is specifically for model-backed creation/editing/decomposition. The first cloud adapter is OpenAI image generation through the Responses API, but all public contracts remain provider-neutral.

**Tech Stack:** Node >=22 native `fetch`, TypeScript 5.8, existing `JobScheduler`/`JobStore`, SHA-256 content addressing, v3 project schema/timeline engine, mocked HTTP tests.

**Spec:** `docs/superpowers/specs/2026-10-09-flicksmith-v0.5-agent-native-creative-platform-design.md`

## Global Constraints

- Generation providers are optional; existing projects must open/edit/render offline.
- Credentials come from process/runtime configuration only and are never serialized into `.flick.json`, receipts, logs, fixtures, or generation records.
- Provider output is immutable evidence; regeneration creates a new asset/record rather than overwriting prior output.
- Failed, rejected, cancelled, or budget-blocked generation must not mutate canonical project state.
- Provider contracts must expose capabilities rather than leaking vendor-specific assumptions into Studio/MCP.
- Accepted outputs must be content-addressed and have provider/model/prompt/input/parameter/usage/rights provenance.
- Project format remains version 3 with optional new fields.

## Review Focus

- Cancellation after provider response but before acceptance must leave project state unchanged.
- Duplicate identical output bytes must deduplicate by content hash while preserving separate generation records if requests differ.
- Missing/expired credentials must fail as runtime errors without appearing in persisted error text.
- Provider capability mismatch must fail before network execution.
- A generation record referencing an unknown asset must fail v3 schema validation.

### Task 2: Define provider-neutral generation contracts

**Files:**
- Create: `packages/generation/src/types.ts`
- Create: `packages/generation/src/registry.ts`
- Create: `packages/generation/src/index.ts`
- Create: `packages/generation/test/registry.test.ts`

**Interfaces:**
- Produces:

```ts
export type GenerationKind = 'image'|'image-edit'|'layer-decomposition'|'inpaint'|'depth'|'video'|'audio';

export interface ProviderCapabilityManifest {
  provider: string;
  kinds: GenerationKind[];
  execution: 'local'|'cloud';
  supportsTransparency: boolean;
  supportsMasks: boolean;
  supportsReferences: boolean;
  supportsStreaming: boolean;
  supportsCancellation: boolean;
  maxWidth?: number;
  maxHeight?: number;
  estimatedUnit?: 'request'|'image'|'second'|'token'|'unknown';
}

export interface GenerationRequest {
  id: string;
  projectId: string;
  kind: GenerationKind;
  prompt?: string;
  inputAssetIds: string[];
  parameters: Record<string, unknown>;
  provider?: string;
  model?: string;
  budget?: { maxCostUsd?: number; maxUnits?: number };
}

export interface StagedGenerationOutput {
  requestId: string;
  provider: string;
  model: string;
  outputs: Array<{ path:string; mediaType:string; sha256:string }>;
  usage?: { units?:number; costUsd?:number };
  rights?: { commercialAllowed?:boolean|null; attributionRequired?:boolean; policy?:string };
  providerMetadata?: Record<string, unknown>;
}

export interface GenerationProvider {
  manifest(): ProviderCapabilityManifest;
  generate(request: GenerationRequest, signal: AbortSignal): Promise<StagedGenerationOutput>;
}
```

## Release Gate

v0.5b is complete only when a provider can generate an image into staging, cancellation/rejection leaves the project byte-for-byte unchanged, explicit acceptance creates content-addressed canonical assets plus complete provenance, no credential material can be serialized, and all generation behavior is available through provider-neutral contracts.
