# FlickSmith v0.5c Generated Scene Assets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn an accepted still image into an editable native FlickSmith scene by decomposing it into RGBA elements, completing hidden regions, estimating depth, assembling v3 motion layers/camera, and applying deterministic 2.5D motion.

**Architecture:** Add a focused `packages/generated-scenes` orchestration layer on top of the v0.5b provider runtime. The router prefers true multi-RGBA decomposition, falls back to segmentation + clean-plate inpainting, and skips decomposition for already-transparent isolated assets. All final scene structure is normal v3 `MotionComposition`/`MotionLayer` data; provider-generated video is represented only as an optional flattened fallback asset.

**Tech Stack:** TypeScript 5.8, v3 motion schema/timeline, v0.5b generation providers, image metadata/alpha analysis, depth maps, existing compositing/design-QC packages, Node tests with fixture images/providers.

**Spec:** `docs/superpowers/specs/2026-10-09-flicksmith-v0.5-agent-native-creative-platform-design.md`

## Global Constraints

- Native 2.5D is the release-gating default; image-to-video generation cannot be required for the acceptance film.
- Generated scene elements must remain ordinary editable v3 image layers, cameras, masks, mattes, effects, and keyframes.
- Critical text/CTA/UI copy stays native text/vector data, never baked into generated imagery by this subsystem.
- Decomposition uncertainty and incomplete clean plates must surface as diagnostics.
- Every provider-created intermediate asset retains its own generation provenance.
- Scene assembly is transactional and revision-safe.
- Flattened image-to-video output must be explicitly labeled `flattenedGeneration: true` in asset metadata/provenance.

## Review Focus

- Foreground motion that reveals missing background pixels must be blocked/warned rather than rendering unexplained holes.
- Incorrect or flat depth maps must not create extreme Z separation or unsafe camera motion.
- Alpha fringes/halos around decomposed layers must be detected by QC.
- A scene with one transparent object plus a background must bypass unnecessary decomposition.
- A provider timeout midway through decomposition must leave no half-attached `generatedScenes` entry.

## Release Gate

v0.5c is complete only when a still can be turned into a multi-layer v3 scene with a camera and editable native motion, the system detects/repairs hidden-region risks, the scene survives save/reload/render, generation provenance remains intact, and the release acceptance film requires no image-to-video generation.
