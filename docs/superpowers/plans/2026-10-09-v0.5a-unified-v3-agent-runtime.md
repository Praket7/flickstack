# FlickSmith v0.5a Unified V3 Agent Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose FlickSmith's existing professional v3 motion engine through one revision-safe MCP/agent contract so agents can create and edit professional motion projects without arbitrary scripts.

**Architecture:** Reuse `V3ProjectSession` and `V3EditOperation` in `packages/timeline/src/v3.ts` as the only mutation authority. Add a dedicated v3 MCP host and catalog, route project version 3 through it, and keep persistence atomic through the existing desktop runtime. All mutating tools require `expectedRevision`, emit the existing v3 receipt/checkpoint result, and never accept executable payloads.

**Tech Stack:** Node >=22, TypeScript 5.8, MCP JSON-RPC, existing v3 schema/timeline engine, atomic project writes, Node test runner.

**Spec:** `docs/superpowers/specs/2026-10-09-flicksmith-v0.5-agent-native-creative-platform-design.md`

## Global Constraints

- `.flick.json` remains canonical state.
- Project format remains version 3; do not introduce v4 for this release.
- Every meaningful mutation must be typed, revision-safe, checkpointed, and return an Intent Receipt.
- No shell, `eval`, arbitrary JavaScript, opaque executable payload, or credential field may enter project state.
- Preserve semantic locks and locked layers through the existing v3 mutation engine.
- Node runtime floor is `>=22` and the repository test command remains `npm run verify`.
- Existing v1/v2 MCP clients must continue to work unchanged.

## Review Focus

- Stale `expectedRevision` must return a conflict and leave project bytes unchanged.
- Locked layers must reject mutation even when invoked through MCP.
- Malformed nested payloads must fail schema validation instead of partially mutating state.
- Project v1/v2 routing must remain backward compatible.
- A successful MCP mutation persisted to disk must round-trip through `parseProjectV3` with the same revision.

## Release Gate
