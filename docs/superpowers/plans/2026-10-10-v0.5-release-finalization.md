# FlickSmith v0.5 Finalization and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish FlickSmith v0.5 on top of the verified v0.4 native/product base, make both JavaScript/TypeScript and native Rust release gates green, preserve the agent-safety contract, and merge PR #1 only from a fully verified head.

**Architecture:** v0.5a through v0.5f are integrated on `feature/flicksmith-v0.5-final`. The finalization phase does not add a new project format or bypass the canonical v3 engine. It stabilizes the integrated platform, removes temporary diagnostics, verifies the full CI/native matrix, and records release evidence before merge.

**Tech Stack:** Node >=22, TypeScript 5.8, Node test runner, Rust 1.90, Cargo/Clippy/Rustfmt, WGPU, Tauri 2, FFmpeg, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-09-flicksmith-v0.5-agent-native-creative-platform-design.md` on the original planning branch `feature/flicksmith-v0.4-professional-motion-engine`.

## Global Constraints

- The verified v0.4 native/product base remains the foundation; do not replace it with the old planning branch.
- `.flick.json` remains canonical state and project format remains v3 for v0.5.
- Every canonical creative mutation remains typed, revision-safe, checkpointed, receipt-producing, and lock-aware.
- No shell, `eval`, arbitrary JavaScript, opaque executable payload, raw filesystem bypass, or credential field may enter project state.
- Generation stays provider-neutral and transactional; failed/cancelled/rejected jobs do not mutate canonical project state.
- Generated Scene Assets remain structured/editable by default; flattened generated video is never the canonical representation when native layers can represent the scene.
- Critical titles, CTA copy, UI labels, and brand text remain native text/vector layers where practical.
- Release claims require measured evidence; do not claim GPU/native performance from generic CI metadata alone.
- PR #1 must not merge until both `CI` and `FlickSmith v0.4 Native Verification` succeed on the same final head SHA.
