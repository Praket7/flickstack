# FlickSmith Agent Guide

`project.flick.json` is canonical. Use typed reversible operations, revisions, checkpoints, Semantic Locks, Intent Receipts, provenance, and Video Git. Do not replace project state with ad-hoc FFmpeg, React, shell scripts, or opaque executable payloads.

Before generation, search existing evidence and resolve the Coverage Graph. Generate only a justified coverage gap or an intentionally synthetic art-directed moment. Accepted generated media must keep provenance and should become editable native scene structure whenever possible.

## Creative standard

Do not default to the recognizable “AI ad” language of equal-length shots, repeated push-ins, glossy gradients, floating centered type, transition spam, constant motion, beat-matched cuts, or music-only sound. Read `docs/human-crafted-creative-system.md` and use `packages/creative-quality`.

Every shot needs a reason to exist. Camera movement must reveal, follow, emphasize, or reframe something. Build narrative progression, brand-specific typography and composition, deliberate pacing, tactile sound, continuity, and purposeful restraint. Preserve authentic texture and performance when useful. Never fake humanity with random jitter, noise, timing errors, or arbitrary imperfection.

Before delivery, run technical QC and the human-craft gate. Repair the smallest affected range instead of regenerating the whole piece.

## Capability honesty

Work/Codex or another execution-capable environment can clone the repository, run the renderer, inspect files, and use the full local toolchain. Normal ChatGPT can use the MCP/plugin tool surface when a FlickSmith backend is connected and can perform high-quality planning/review with the chat-facing craft tools, but a text-only chat cannot execute local Node, FFmpeg, Rust, GPU, or filesystem work by itself. Never claim unavailable capabilities.
